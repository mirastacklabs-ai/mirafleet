# M2 — Central core: implementation plan

Parent: [PLAN.md](PLAN.md) M2. Design: [ARCHITECTURE.md](ARCHITECTURE.md).
Every step keeps `scripts/dev.sh fmt|build|vet|test|cross` green.

## 1. Design decisions

### 1.1 Store
- `internal/store`: `Store` interface with domain-level atomic methods (`Enroll`, `SetRunnerStatus`,
  …; ~6 atomic ops). Rejected: generic `WithTx` (leaks SQL, harder fakes/Postgres later).
- Times INTEGER unix ms UTC. Keys stored as SSH wire BLOB + fingerprint TEXT; `ssh-ed25519` only.
- Tables (AUTOINCREMENT everywhere: IDs never reused — revoke tombstones rely on it):
  - `fleets(id, name UNIQUE, mode CHECK('actions','workspace'), confirm, created_at)`
  - `runners(id, fleet_id FK RESTRICT, name, pubkey BLOB UNIQUE, fingerprint, status
    CHECK('pending','active','disabled','revoked'), labels JSON, join_token_id FK SET NULL, info JSON,
    created_at, updated_at, last_seen_at)` + `UNIQUE(fleet_id,name) WHERE status<>'revoked'`
    (revoked names reusable; revoked keys never re-enrol).
  - `join_tokens(id, token_id UNIQUE, secret_hash, fleet_id FK CASCADE, labels JSON, auto_approve,
    max_uses ≥1, uses, expires_at NOT NULL, revoked_at, created_by, created_at)`
  - `operators(id, name, pubkey BLOB UNIQUE, fingerprint, status CHECK('active','revoked'),
    created_at, updated_at, last_seen_at)` + partial unique `name WHERE status<>'revoked'`
  - `settings(key TEXT PK, value BLOB)` — holds the operator registration secret (§1.3)
  - `audit(id, ts, source, actor_kind, actor, remote, fleet, runner, subject, action, params JSON,
    outcome, exit_code, duration_ms, message, request_id)`: denormalised names, no FKs, indexes on
    `ts` and `(fleet,runner)`, `BEFORE UPDATE/DELETE … RAISE(ABORT)` (append-only).
- Migrations: embedded `internal/store/sqlite/migrations/NNNN_*.sql`, forward-only,
  `PRAGMA user_version`, each in `BEGIN IMMEDIATE … COMMIT`; a newer DB than the binary fails
  closed; a test enforces contiguous numbering. Rejected: goose/golang-migrate (deps), ad-hoc DDL.
- Pragmas per connection via DSN: `foreign_keys(1) journal_mode(WAL) busy_timeout(5000)
  trusted_schema(0) synchronous(FULL)` — FULL so a committed revoke survives power loss.
- Two pools: writer `MaxOpenConns(1)` + `_txlock=immediate`; reader ~4 conns `query_only(1)`.
  Rejected: one multi-conn pool (WAL read→write upgrade = instant SQLITE_BUSY), one conn (stalls).
- Central sets `umask 077` at start (db, -wal, -shm are 0600). Tests use a temp file under
  `t.TempDir()`, never `:memory:` (per-connection DBs). Heartbeats stay in memory; `last_seen_at`/
  `info` written on connect, disconnect and at most every 5 min.

### 1.2 Join tokens
- Format `mfj1.<id:16 hex>.<secret:43 b64url>.<hostkey-sha256:43 b64url>`; the host-key hash pins
  central on join (no TOFU). Secret 32 random bytes; store SHA-256 only, look up by id,
  constant-time compare (no bcrypt: 256-bit random secret).
- Default single-use, TTL 24h; `-uses N` (capped), `-ttl` (≤30d); never unlimited. `-approve` joins
  as active, default pending. Consumption: conditional `UPDATE … uses<max_uses …` with
  RowsAffected=1 in the same tx as the runner insert. Secret printed once, never logged/audited;
  CLI accepts tokens on stdin (`-`).

### 1.3 Auth and enrolment (SSH keys only)
- `AuthProvider.Authenticate(meta, key) (Principal, error)` in `PublicKeyCallback`; SSH user binds
  role: `runner`, `operator`, `enroll`. Unknown/revoked keys rejected except user `enroll`.
  Identity travels only in `Permissions.Extensions` (never callback closure state —
  CVE-2024-45337); handler reloads principal by id. `MaxAuthTries=3`.
- `enroll` connections: any ed25519 key, 30 s deadline, exactly one channel — `join@mirafleet`
  (token, name, labels) or `register@mirafleet` (operator name, registration code) — then closed.
  Enroll connections are rate-limited per source address (default 10/min) and failures are logged.
- `runner join`: generate key, dial with token-fingerprint host-key callback, write `known_hosts`
  and `<data>/runner.yaml`; refuses an already-joined data dir (Q13). Token labels are trusted;
  heartbeat labels are informational only.
- **Operator registration: rotating TOTP-style code (user decision).** No open registration, no
  pending operators, no approval step.
  - `central init` creates a 32-byte registration secret (`settings`, never logged/audited).
    `central operator rotate-secret` replaces it (invalidates every outstanding code).
  - Code for time step `s = floor(unix_seconds / 60)`:
    `mfr1.<base32(HMAC-SHA256(secret, "mirafleet-register-v1" ‖ s))[:26]>.<hostkey-sha256 b64url>`
    — 128-bit, RFC 6238-style but long (not 6 digits) so it cannot be brute-forced in its window;
    the host-key hash pins central on login (no TOFU), like join tokens.
  - Valid only within its own 60-second step (central both issues and checks, so there is no clock
    skew); it expires when the step ends. Constant-time compare. **Not single-use:** any number of
    operators may register with the same code inside its window (user decision).
  - `mirafleet central operator code` (local admin socket, admin only) prints the current code and
    the seconds left in its window; showing a code is audited (who, when), the code itself is not.
    The M4 GUI shows the same on central.
  - Operator: `mirafleet mcp login <addr> -name N -code -` (code on stdin, never in argv/history).
    A valid code registers the key as **active** directly: only someone with admin access on
    central can read the code, so the code is the approval. A leaked code is useless once its
    60-second window ends. Re-registering an already active key is idempotent; every registration
    is audited with the operator name, key fingerprint and source address.
  - Key/known_hosts live in `os.UserConfigDir()/mirafleet/`.
- Windows client keys: DACL check in M5; until then the Windows key loader fails closed.

### 1.4 `api@mirafleet` protocol (`internal/api`, pure Go, cross-platform)
- One request per channel; cancel = close channel; concurrency = more channels.
  Rejected: multiplexed JSON-RPC channel, ExtraData payloads.
- Frames: 4-byte big-endian length + JSON, length checked before allocation. Rejected: NDJSON (Q12).
- Request `{"v":1,"id","method","params"}` with `DisallowUnknownFields`; response
  `{"v":1,"id","result"}` or `{"error":{"code","message"}}`. Unknown `v` → `unsupported_version`
  + supported list. Codes: `bad_request unauthenticated forbidden not_found conflict unavailable
  too_large timeout unsupported_version internal` (internal messages generic).
- Methods on `api@mirafleet` (operators): `hello`, `fleets.list`, `runners.list{fleet}`,
  `action.run{fleet,runner,action,params,timeout_s,confirm}`. Nothing else.
- **Lifecycle and admin only through central (user decision).** Runner lifecycle
  (approve/disable/enable/revoke), operator revoke, fleets, join tokens, registration codes and
  `audit.list{since_id,limit}` exist only on the local admin socket (CLI on central) and, from M4,
  the GUI served by central. They are never dispatched on `api@mirafleet`, whatever the
  principal, and the M5 `runner_lifecycle` MCP tool is dropped.
- Limits (Q12): request ≤64 KiB; response ≤ MaxResultBytes+64 KiB; request within 10 s; lists 10 s;
  `action.run` min(timeout_s,10m), default 2m; ≤8 concurrent channels per operator connection;
  ≤32 params, key ≤64 B, value ≤4 KiB; names regex-validated.

### 1.5 Local admin socket (kept, re-based)
Same unix socket, 0600, umask 077, peer-UID check — now speaking `internal/api` framing and
limits, principal `admin` (`local:uid=N`), source `cli`, same dispatcher as `api@`. Needed because
revoke must reach live connections. Rejected: CLI writing the DB directly (registry drift);
CLI over SSH with a bootstrap admin key. Admin commands need a running central; only
`central init` (host key + migrated DB) is offline. M4 GUI calls `service` in-process (source `gui`).

### 1.6 Revoke propagation (Q11)
`internal/central/registry` keys sessions by DB id; each session has a cancel-on-kick context.
`Service.RunnerLifecycle(revoke)`: (1) under the registry lock add a tombstone, cancel the session
context, close the SSH conn; (2) commit `status=revoked` + audit; (3) on commit failure remove the
tombstone. First-heartbeat registration checks tombstone + status under the same lock (closes the
auth-before-commit gap); later auth is rejected from the DB. Exec contexts derive from request +
session contexts; runner side kills the process group (M1). Audit outcome `cancelled`,
message `runner revoked`. Operator revoke (central only) kicks their connections and cancels
their execs.
`disable`: refuse new work, let in-flight finish. Pending runners may heartbeat but never exec.

### 1.7 Audit
SQLite `audit` is the source of truth. State changes write their audit row in the same tx. Exec
writes a `start` row before dispatch (fail closed if it fails) and an outcome row (same
`request_id`). `audit.Sink{Record(ctx, Event) error}` — SQLite store on central, existing JSONL
writer on runner. `audit.Event` gains omitempty Source, ActorKind, Actor, Remote, Fleet, Subject,
RequestID. Sources: `cli api gui enroll system`; an `mcp` hint from `hello` is recorded, not
trusted. Auth failures / bad-token joins are logged, not audited. No retention in M2.
Enterprise seam: SIEM export tails `audit.list since_id`.

### 1.8 Other interfaces
- `PolicyEngine.Authorize(ctx, Principal, Action, Resource) error`; OSS table: local admin all;
  active operator `hello`/list/run only; anything else denied. Deny by default. Admin methods are
  additionally absent from the `api@` method table (two independent gates).
- Service-side checks: fleet mode `actions` for `action.run`; `confirm == fleet` on guarded fleets;
  runner `active`.
- `internal/service`: the single code path for CLI, api, GUI, MCP. Depends on `Store`,
  `PolicyEngine`, `audit.Sink`, `Live` (registry: Exec, Kick, Tombstone, Snapshot), injected `now()`.
- Data-dir lock (Q13): `flock` on `<data>/central.lock`; a second central on the same dir fails.

### 1.9 Migrating M1
Remove `authorized_runners`, `keys.ParseAuthorized` (+tests), `central -init`/`runner -init`
(→ `central init`, `runner join`), central `audit.jsonl` (→ table). No importer (M1 never
deployed). Move `Server.exec`, `sessionFor`, `watch` into `registry` unchanged. Port M1 integration
tests to a store-seeded `newEnv`; every M1 property (Q01–Q18) must still pass. Runner changes only
SSH user `runner` + `runner.yaml`; actions guard untouched. Central/runner wiring moves to
`cmd/mirafleet/server_linux.go` (+ fail-closed `server_other.go`) so darwin/windows binaries never
link SQLite; `internal/store/sqlite` must still compile on all six targets.

## 4a. Rules from the Wave A review (binding for later steps)
- `ssh.Channel` has no read deadline: request reads on `api@` and enroll channels use
  `api.ReadRequestTimeout`, which closes the channel when `RequestTimeout` expires.
- `Store.Enroll` order: look up token id → constant-time compare (against a dummy hash when the
  id is unknown) → staleness. The service (S6) maps not-found, wrong secret and stale to one
  identical joiner-facing error.
- Every store mutator takes `now`; nothing below the service calls `time.Now()`.
- `central init` creates the registration secret with `CreateSetting` (fails if present);
  only `operator rotate-secret` overwrites it.
- S6: idempotent operator re-registration is still audited; a key may belong to a runner or an
  operator, never both (checked in the service on enrol and register).
- Name, mode and limit validation failures return `store.ErrInvalid` → `bad_request`.
- Token and code formats live in `internal/tokens` (pure Go, cross-platform, shared by central
  and the client): format/parse `mfj1.` join tokens and `mfr1.` registration codes, host-key
  hash helper, constant-time compare, and the registration-code HMAC (`Code(secret, step)`,
  `Step(now)`). `internal/service` generates/verifies with it; `internal/apiclient` parses.
- Enroll channels (`join@mirafleet`, `register@mirafleet`) carry exactly one `internal/api` frame
  each way: request methods `enroll.join{token,name,labels}` / `enroll.register{code,name}`,
  separate from the operator and admin method sets (`api.IsEnrollMethod`).
- `tokens.VerifyCode` takes the 26-char code body: callers run `tokens.ParseCode` first and also
  check that the code's host-key hash matches central's own key.
- Registry is deny-by-default: only `active` sessions exec; unknown statuses are rejected.
  `SetStatus` records the status per id even while the runner is offline, and `Register` applies
  that recorded status over the caller's (closes the load-then-register race; no DB I/O under the
  registry lock). The service calls `SetStatus` after every committed status change.
- `action.run` `confirm` is a string that must equal the fleet name on guarded fleets (typed by
  a human or the harness prompt), never a boolean.
- Runner/operator key disjointness is enforced atomically in the store (cross-table check inside
  the `Enroll` and `RegisterOperator` transactions), not check-then-insert in the service.
- `service.Config.OperatorConns` is required; S7 implements it and tests that revoking an operator
  cancels their in-flight `action.run`. S7 handlers map service views to `api` DTOs only
  (`RunnerView` → `api.RunnerInfo`); store rows never go on the wire.
- S7: move the channel-type and SSH-user constants (`ChanAPI`, `ChanJoin`, `ChanRegister`,
  `UserOperator`, `UserEnroll`, `UserRunner`) from `internal/apiclient` into
  `internal/transport`, so central never imports the client package.

- D-01 (P3) `internal/runner` `TestBackoffGrowsWhenConnectionNeverHealthy` is timing-sensitive

  kick stays connected (unprivileged): after `add`, reload by id and close if not active.
- D-05 (P2) tests: foreign-UID peer rejected on the admin socket before any read (seam for the UID
  getter); client disconnect cancels an admin `action.run`; RSA/ECDSA/cert keys refused for every

- D-07 (P3) cross-check `enrollKey` against `p.Fingerprint`.
- D-08 (P3) runner touches: async/coalesced, throttle connect/disconnect writes, use `cfg.Now`;

- D-09 (P3) write deadline on responses (close the channel on timeout).
- D-10 (P3) `Close()` waits for handshaking conns; `ServeAdmin` wg.Add race at shutdown.
- D-11 (P3) enroll limiter: hard-cap the map; bucket IPv6 by /64.
- D-12 (P3) log forbidden admin/enroll method attempts on api@.
- D-13 (P3) `deps_test`: positive control (linux links sqlite) and fail in CI if `go` is missing.
- D-14 (P3) `admin_unix_test.go` goroutine leak; overlap between the two operator-revoke tests.

## 6. Decisions (13 Nov 2026)
1. Operator registration: rotating TOTP-style registration code from central, valid for its
   60 s step, usable by any number of operators within that window (§1.3).
2. Runner lifecycle and all admin operations: only through central (local CLI, M4 GUI); never
   over `api@mirafleet` or MCP (§1.4).
3. Dependencies: `modernc.org/sqlite` and its transitive modules approved. Licence policy scope is
   code linked into the binary (what go-licenses checks); public-domain SQLite accepted. Any
   non-permissive linked module stops the step for the user's call.
4. Defaults taken unless overridden: operator CLI is `mirafleet mcp login` / `mirafleet mcp api`;
   `runner join` prints the systemd next step (unit ships with M6 packages); no importer for
   M1 `authorized_runners`.
