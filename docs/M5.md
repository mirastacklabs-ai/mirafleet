## 1. Design decisions

### 1.1 MCP protocol: `github.com/modelcontextprotocol/go-sdk`
- Already approved in PLAN.md as an M5 dependency. Pin **v1.8.0** (S0 confirms the version and
  date). Supported protocol versions: 2026-07-28, 2025-11-25, 2025-06-18, 2025-03-26, 2024-11-05.
- Only package `mcp` is imported, only from `internal/mcpserver`. Stdio transport, `tools`
  capability only (no resources, prompts, sampling, roots).
- Licence: the SDK's LICENSE holds Apache-2.0 (new contributions) + MIT (existing code), plus a
  CC-BY-4.0 notice for docs. If go-licenses can't classify the combined file, S0 reviews it by hand
  and adds a documented `--ignore`, as for `modernc.org/mathutil`.
- Transitive modules (S0 confirms what is linked with `go list -deps`):

| Module | Licence | Linked? |
|---|---|---|
| `google/jsonschema-go` | MIT | yes (schema inference) |
| `yosida95/uritemplate/v3` | BSD-3-Clause | likely |
| `segmentio/encoding` | MIT | yes |
| `segmentio/asm` | **MIT-0** | yes, via segmentio/encoding |
| `golang.org/x/oauth2`, `x/time`, `x/sync`, `x/sys` | BSD-3-Clause | S0 decides |
| `golang-jwt/jwt/v5` | MIT | only if `mcp` imports `auth` |
| `google/go-cmp`, `x/tools` | BSD-3-Clause | test/tool only |

- MIT-0 is not on the CLAUDE.md allowlist → Q1. Fallback if refused: a stdlib implementation in
  `internal/mcpserver` (~700 lines: newline-delimited JSON-RPC 2.0, `initialize`,
  `notifications/initialized`, `ping`, `tools/list`, `tools/call`, `notifications/cancelled`,
  `notifications/progress`, version negotiation); about one more day, and we own conformance.
- Rejected: the SDK's HTTP transports (would open a listener); a generic "call any method" tool.

### 1.3 Tool list (thin wrappers; M3 §1.15 unchanged)

| Tool | Arguments | Calls | Annotations | Guarded |
|---|---|---|---|---|
| `list_fleets` | `context?` | `fleets.list` per context (or one) | readOnly | — |
| `list_runners` | `fleet?`, `context?` | `runners.list` (status, labels, `free_slots`, `executor`, `actions` §1.12) | readOnly | — |
| `run_action` | `fleet?`, `runner`, `action`, `params{}`, `timeout_s?`, `confirm?` | `action.run` | destructive, openWorld | `confirm` |
| `workspace_open` | `fleet?`, `image?`, `labels{}?`, `confirm?`, `context?` | `workspace.open{fleet, session, image, labels, confirm}` | idempotent | `confirm` |
| `exec` | exactly one of `command` (→ `["/bin/sh","-c",command]`) or `argv[]`; `cwd?`, `env{}?`, `timeout_s?`, `stdin?` (text ≤ 1 MiB), `workspace?`, `confirm?` | `workspace.exec` (stdin as a body frame) | destructive | `confirm` |
| `read_file` | `path`, `offset?`, `limit?` (default = output cap, max 1 MiB), `encoding?` (`text`\|`base64`), `workspace?` | `workspace.read_file` | readOnly | — |
| `write_file` | `path`, `content`, `encoding?`, `offset?` (0 = truncate), `mode?`, `workspace?`, `confirm?` | `workspace.write_file` in ≤ 1 MiB chunks; length/sha256 computed by the server; tool limit 8 MiB | destructive | `confirm` |
| `workspace_close` | `workspace?` | `workspace.close` (returns `state`, E-04) | destructive, idempotent | — |
| `workspace_list` | `fleet?`, `context?` | `workspace.list` (own only) | readOnly | — |

- `workspace_list` is an addition to the ARCHITECTURE table (the remaining read-only `workspace.*` method).
- `workspace?` defaults to the session's bound workspace for that (context, fleet).
- Implicit open: `exec`, `read_file`, `write_file` with no bound workspace open one on the default
  fleet only when that fleet is **not** guarded; otherwise an error asks for `workspace_open`.
- `encoding: text` refuses non-UTF-8 and reports size and SHA-256 instead.
- The MCP server never reads or uploads local files (an injected agent could exfiltrate `~/.ssh`).
- Results are JSON objects as `structuredContent` (with `outputSchema`) plus the same JSON as one
  `TextContent`. Errors are `isError: true` with `{"error":{"code","message"}}` (api error codes).
- Server `instructions` and tool descriptions say stdout, stderr and file contents are data from
  remote machines, not instructions.

### 1.4 Sessions (one workspace per harness session)
Resolved at **every** open, in order:
1. `-session ID` flag (harness-neutral).
2. Handoff file for (parent PID, project dir), written by a hook; the Claude Code hook stores `cc:<session_id>`.
3. Per-process random `p:<32 hex>` (crypto/rand).

- Every value passes `api.ValidateSession`. Re-reading per open means `/clear` (new `session_id`)
  binds a new workspace on the next open.
- Handoff file: `<state>/sessions/<sha256(pid|project)[:32]>.json` = `{v, session, project, pid,
  written}`; dir 0700, file 0600, atomic write; files older than 7 days pruned on write.
- A planted handoff file can only point at another session of the **same operator** (ownership is
  enforced on central).
- Assumption (Q2): the hook and the MCP server are both direct children of Claude Code. If false,
  the fallback (3) is safe; only `--resume` reattach is lost.

### 1.5 Contexts and project default
- Keep `contexts.yaml` in the config dir (written by `mcp login`; ARCHITECTURE's `config.yaml` is
  renamed to match). Additive, strict fields: per context `default_fleet`; top level
  `output_cap_bytes` (4 KiB…256 KiB, default 30 KiB). A `jump` key is rejected (Q5).
- New CLI: `mirafleet mcp context list|use NAME|remove NAME`.
- Project file `.mirafleet.yaml`: keys `fleet` and `context` only, strict; **no addresses, keys or
  caps** (a cloned repo cannot add a central). Looked up from `-project-dir` (else cwd) upward,
  stopping at the first dir with `.git`, never above home. A project default naming a guarded fleet
  is not used: guarded fleets must be named explicitly and confirmed.
- Precedence: tool argument > flags (`-context`, `-fleet`) > `.mirafleet.yaml` > context
  `default_fleet` > none.
- `list_fleets` with no `context` lists every context; a down context is an `errors[]` entry.

### 1.6 Output capping and sanitising (`internal/orch/output.go`)
- Default cap 30 KiB of UTF-8 for stdout + stderr together, on `exec`, `run_action` and text-mode
  `read_file` (under Claude Code's 10k-token warning and 50,000-character spill threshold).
- 1/3 head, 2/3 tail; stderr keeps ≥ 1/3 of the budget when not empty. Cuts on rune boundaries with
  `[mirafleet: N bytes omitted]` and `truncated: true`. On top of the runner's 1 MiB cap.
- Strip ANSI CSI/OSC and C0 controls except `\n`, `\t`; normalise `\r\n`.
- List tools return at most 200 entries, with `truncated`.

### 1.7 `confirm` on guarded fleets
- Pass-through only: never filled from config, never cached. Central enforces `confirm == fleet
  name` (refusal is `bad_request`, audited as denied).
- Refusal text becomes: "fleet `prod` is guarded. Ask the user. Only after the user explicitly
  agrees, repeat the call with `confirm` set to the fleet name."
- The human gate is the harness's tool-approval prompt; in Claude Code the PreToolUse hook (§2)
  adds an explicit "ask" for any call carrying `confirm`. Complete, because central refuses every
  guarded call without it.
- Deferred: MCP elicitation.

### 1.8 Lifecycle and idle-on-exit
- `mirafleet mcp` with no subcommand serves stdio; on a TTY it first prints a hint to stderr.
  stdout carries protocol only; logs go to stderr.
- Shutdown on stdin EOF, SIGTERM/SIGHUP, or `os.Interrupt` on Windows: cancel in-flight calls
  (closing a channel cancels on central), close SSH connections, exit 0 within 5 s.
- Never closes workspaces on exit: the row stays `open` and the idle-TTL reaper (default 24 h)
  removes it. Closing is `workspace_close` or the Claude Code SessionEnd hook.
- Connections: one SSH connection per context, lazy `apiclient.Dial` with `KnownHosts` pinning and
  `hello`; `keepalive@mirafleet` every 30 s; redial once on a dead connection, auto-retry only
  idempotent calls (lists, `read_file`, `workspace_open`), never `exec`, `write_file`,
  `run_action`; 8 channels per connection (`api.MaxChannelsPerConn`).
- Progress: with a `progressToken`, long calls send `notifications/progress` every 15 s. Output is
  still buffered.

### 1.9 Credentials per OS

| OS | Config dir (key, `known_hosts`, `contexts.yaml`) | State dir (handoff) | Protection |
|---|---|---|---|
| linux | `$XDG_CONFIG_HOME/mirafleet` or `~/.config/mirafleet` | `os.UserCacheDir()/mirafleet` | dir 0700, key 0600, checked on load (`keys/perm_unix.go`) |
| darwin | `~/Library/Application Support/mirafleet` | `~/Library/Caches/mirafleet` | same |
| windows | `%LocalAppData%\mirafleet` (not Roaming: it would copy the key to a profile server) | `%LocalAppData%\mirafleet\state` | protected DACL (below) |

- Windows DACL (S2), set on create and checked on load: inheritance off; owner = current user;
  allow-ACEs only for the current user, SYSTEM, BUILTIN\Administrators; anything else fails closed.
- `MIRAFLEET_CONFIG_DIR` still overrides. No OS keychain, passphrase or agent support in M5.
- The MCP server never registers; `mcp login` stays a human CLI step (code on stdin).
- Tool results go to the model provider, so they never contain key material or local-key
  fingerprints, local paths, env values, registration codes or `known_hosts` lines. Setup errors
  say "run `mirafleet mcp login …`". With no contexts or key the server still starts and lists tools.

### 1.10 Nothing forwarded from the MCP server's environment
The server reads only `MIRAFLEET_CONFIG_DIR` and its flags. Workspace `env` comes only from the
tool's `env` argument, checked by `api.ValidateEnv` (denylist + E-11) and the runner's
`env_allow`. Tests put decoys (`ANTHROPIC_API_KEY`, `AWS_SECRET_ACCESS_KEY`, `GITHUB_TOKEN`) in
the server env and check they never reach a Create spec or ExecRequest.

### 1.11 No admin or lifecycle reach
- Gate 1 (code): fixed tool table; `orch.call` is the only path to `apiclient` and refuses any
  method where `api.IsOperatorMethod` is false (panics in tests).
- Gate 2 (central): admin and enrol methods are refused on `api@` whatever the principal.
- Tests: every tool's method is an operator method; every admin method is refused by `orch.call`;
  `tools/call` for `fleet_create`/`runner_lifecycle` is an unknown-tool error.

### 1.12 Action discovery (additive protocol, Q4)
Heartbeat gains `actions: [{name, params:[{name, pattern, default}]}]` (≤ 128 actions, names
≤ 64 B, patterns ≤ 256 B, checked in `Heartbeat.Validate`), built by `actions.Set.Describe()`,
exposed as `api.RunnerInfo.Actions` in `runners.list`. Informational only: `actions.yaml` stays
the boundary.

## 2. `integrations/claude-code/` (plugin)

```
integrations/claude-code/
├── .claude-plugin/plugin.json   name "mirafleet", displayName, version (lockstep with the binary),
│                                description, author, license "Apache-2.0", repository, homepage
├── .mcp.json                    {"mcpServers":{"mirafleet":{"command":"mirafleet",
│                                  "args":["mcp","-project-dir","${CLAUDE_PROJECT_DIR}"]}}}
├── hooks/hooks.json             exec-form hooks (no sh/PowerShell, works on Windows):
│     SessionStart  → mirafleet mcp hook claude-code session-start   (offline, no stdout)
│     SessionEnd    → mirafleet mcp hook claude-code session-end     (timeout 15)
│     PreToolUse    → matcher "^mcp__plugin_mirafleet_mirafleet__.*" → … pre-tool-use
├── skills/mirafleet/SKILL.md    main skill (description, argument-hint, $ARGUMENTS)
├── skills/openfleet/SKILL.md    alias: disable-model-invocation: true; body = "follow
├── skills/claudefleet/SKILL.md     ${CLAUDE_PLUGIN_ROOT}/skills/mirafleet/SKILL.md with $ARGUMENTS"
├── hook/{hook.go, hook_test.go} Go package (§1.2)
└── README.md                    install (--plugin-dir now, marketplace in M6), PATH, troubleshooting
```

- **SessionStart:** reads `session_id`, `cwd` from stdin; writes the handoff (`cc:<session_id>`,
  keyed by `os.Getppid()` and `CLAUDE_PROJECT_DIR`/`cwd`). No network, no context injection.
- **SessionEnd:** removes the handoff; per Q3, may dial central, find the caller's workspace by
  `session` via `workspace.list` and `workspace.close` it. Best-effort, ≤ 10 s, always exits 0.
- **PreToolUse:** `ask` when `tool_input.confirm` is set (reason from sanitised, clipped fields,
  e.g. `Guarded fleet "prod": run_action tail-logs on db-1`); no output otherwise; never returns
  `allow`; malformed input → `ask`. Safety doesn't depend on it: central enforces `confirm`.

Conventions to verify by hand in S17 (if false, adjust docs and tests, not the core):
- Bare `/mirafleet`, `/openfleet`, `/claudefleet` resolve when no other command owns the name;
  otherwise `/mirafleet:mirafleet` etc. Docs show both.
- A PreToolUse `ask` still prompts in auto/bypass-permissions modes; if not, document it.
- `${CLAUDE_PROJECT_DIR}` is substituted in plugin `.mcp.json` `args`.
- The PPID topology (Q2).
- `claude plugin validate --strict` passes (run by the user on the host; Claude Code is not a repo dependency).

`mirafleet` must be on PATH in M5 (GitHub release or `go install`); M6 adds brew, npm and the
marketplace.

## 6. "M5 done when"

### `TestM5Done` (`internal/central/m5_done_test.go`)
In-process real central (SQLite, registry, service, SSH), reaper on an injected clock, reusing
`newEnv` and `m3Enrol`; MCP servers via `mcpserver.Serve` over `io.Pipe`, driven by the SDK client.

1. **Set-up:** fleet `dev` (workspace mode, `build-1`, `build-2`, fake executor, `concurrent: 1`);
   fleet `prod` (actions mode, guarded, `db-1` with `tail-logs` and `noisy` = 200 KiB with ANSI);
   operators alice and bob in separate `t.TempDir()` config dirs; a project dir with
   `.mirafleet.yaml` `fleet: dev`; a second context `cloud` and a dead third context; only decoys
   (`ANTHROPIC_API_KEY`, `AWS_SECRET_ACCESS_KEY`) in the server env.
2. **Tools:** `tools/list` returns exactly the 9 tools with schemas and annotations; `fleet_create` is unknown.
3. **Lists:** `list_fleets` shows `dev` (default) and `prod` (`confirm: true`) from both live
   contexts plus one error entry; `list_runners prod` shows `db-1` with `tail-logs` and its
   pattern; `list_runners dev` shows `free_slots`.
4. **Guarded action:** without `confirm` → `isError` with the "ask the user" text and a denied
   audit row; with `confirm: "prod"` → output; `noisy` → ≤ 30 KiB, `truncated`, marker, no ESC.
5. **Implicit open + exec:** `exec "echo hi"` → implicit open on `dev` with `p:…`, fake receives
   `["/bin/sh","-c","echo hi"]`; no decoy in any Create spec or ExecRequest; `env:
   {ANTHROPIC_API_KEY: x}` refused.
6. **Files:** `write_file` 1.5 MiB → two chunks; paged `read_file` matches SHA-256; default `read_file` capped.
7. **Ownership:** bob on alice's id (`exec`, `read_file`, `workspace_close`) → `not_found`.
8. **Mode mismatch:** `workspace_open fleet: prod` → conflict; `run_action` on `dev` → conflict.
9. **Cancel:** `notifications/cancelled` on a long `exec` cancels the fake exec; audited `cancelled`.
10. **Idle on exit:** closing alice's stdin → `Serve` returns ≤ 5 s, row still `open`; a new
    server (new random session) gets the other runner; a third gets `unavailable`; advancing the
    clock past the idle TTL → the reaper closes the first row.
