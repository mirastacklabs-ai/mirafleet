# M3 — Workspaces: decisions

Parent: [PLAN.md](PLAN.md) M3. Design: [ARCHITECTURE.md](ARCHITECTURE.md). Implementation plan below.

## Executor interface
Workspace mode runs behind one runner-side interface; scheduling, TTL reaper, `concurrent: N`
slots, audit and policy stay in mirafleet above it.

```go
type WorkspaceExecutor interface {
    Create(ctx, spec) (id, error)            // image, limits, labels
    Exec(ctx, id, argv, cwd, env, stdio) (exit, error)
    ReadFile(ctx, id, path) (io.ReadCloser, error)
    WriteFile(ctx, id, path, io.Reader, mode) error
    Destroy(ctx, id) error
    List(ctx) ([]Info, error)                // reaper and reconcile
}
```

- `containerd` executor (Go client): the default.
- `opensandbox` executor: opt-in per fleet (decision 13 Nov 2026).

## OpenSandbox executor (opt-in)
[OpenSandbox](https://github.com/opensandbox-group/OpenSandbox) (Apache-2.0, Linux Foundation /
AAIF) provides the sandbox; mirafleet keeps the agent and its API keys outside it and adds
identity, policy, central audit, instant revoke and outbound-only runners.

- **Transport: HTTPS only, never plain HTTP** — not even on loopback. TLS 1.3 via Go's
  `crypto/tls`; the runner pins the OpenSandbox server and execd certificates (fingerprint or a
  private CA configured per node), never the system CA pool; plain `http://` endpoints are
  refused at config load. If OpenSandbox can't serve TLS natively, M3 picks and documents a
  node-local TLS front (decided in the M3 plan, after verifying OpenSandbox's TLS support).
- **No SDK:** the runner speaks OpenSandbox's OpenAPI contracts with the Go standard library only
  — no new module dependency, nothing of theirs linked (their execd module pulls an MPL-2.0
  driver; irrelevant over the wire).
- **Hardened by default, enforced by the runner:** endpoints bound to the node only; refuse to
  start if OpenSandbox's API key is unset (the key lives on the runner host, never in a sandbox);
  bridge networking + egress policy; guarded fleets require a secure runtime (gVisor or Kata);
  no credentials passed into sandbox environments.
- **Verify before building:** OpenSandbox TLS support, transitive licences of what runs on the
  node, Podman/containerd compatibility, API stability (1.x is young).
- Not doing: mirafleet as an OpenSandbox provider, or central calling OpenSandbox directly
  (breaks the outbound-only model and splits the audit trail). Using `opensandbox-mcp` alongside
  `mirafleet mcp` needs no integration.

## Implementation plan (approved 13 Nov 2026)

Parent: docs/PLAN.md M3. Design: docs/ARCHITECTURE.md. Every step keeps `scripts/dev.sh fmt|build|vet|test|cross` green. Steps that touch containerd also keep the new `scripts/dev.sh integration` green.

**Decisions on §7 open questions (13 Nov 2026) — binding, they override the text below where it differs:**
1. User namespaces: `userns: required` by default (hosts without support get 0 slots + a clear error).
2. Egress: proxy-only (stdlib CONNECT/HTTP proxy in the container netns); no CNI, no new dependency.
3. OpenSandbox TLS: **both** — ship `mirafleet runner tls-front` (stdlib, TLS 1.3, **mTLS required**)
   with `mirafleet runner tls-init`, AND document using an existing TLS-terminating proxy (same
   runner-side rules: https only, TLS 1.3, pinned CA/SPKI, client cert).
4. Guarded workspace fleets require a secure runtime (gVisor or Kata) on **both** executors;
   `confirm` = fleet name on `open`, `exec` and `write_file`.
5. Exec timeout is **configurable on central per fleet**: `fleet_workspace.exec_default_s`
   (default 120) and `exec_max_s` (default 1800 = 30 min), admin-set via
   `central fleet create|workspace set -exec-timeout D -exec-max D`; hard ceiling 24 h in code;
   the runner's workspace.yaml `limits.exec_max` also caps it (effective = fleet ∩ runner).
   `mcp api`'s client limit follows the effective value + 30 s.
6. `workspace_open` repo clone with runner-held git credentials: deferred past M3; Claude clones
   via `exec` (no git secrets in workspaces).
7. Private registry pulls: deferred (public images or pre-pulled with `pull: never`).
8. Disk: soft quota in M3; hard quota later.
9. PID 1: read-only bind of the mirafleet binary as `/.mirafleet/init` — the one allowed extra mount.
10. Licence gate: any non-permissive linked module stops the step for the user's decision.

**Wave-C review decisions (13 Nov 2026):**
11. containerd `egress` with a secure runtime (gVisor/Kata) is refused (`egress is not supported with secure runtimes yet`): the in-netns proxy listener does not reach the guest netstack. Guarded fleets therefore run with network `none` until this is verified.
12. OpenSandbox network policy is host-only, so `Create` refuses any egress rule whose port is not 443 or 80; an allowed host is reachable on 80 and 443 only by that rule.

**Rules from wave A (binding for later steps):**
- One source of truth for workspace input checks: `internal/workspace` (`CleanPath`, `ValidArgv`,
  `FilterEnv` + denylist, `MatchImage`). `internal/api` may only delegate to them; no second copy.
- `fleet.workspace_set` is a full replace: the CLI reads the current config, applies the flags,
  and sends the complete `WorkspaceConfig` (so lists like `egress` can be cleared). On
  `fleet.create`, omitted fields take documented defaults — implemented in S16a (today a partial
  config is refused with bad_request).
- Central must call `transport.Heartbeat.Validate()` on every heartbeat and refuse it on error
  (S10); runners use `DecodeWorkspaceRequest` → `WriteResult` → body, central the reverse (S10/S11).
- OpenSandbox TLS: `ca_file` is always required (Go can't verify a chain without a trust anchor
  except via `InsecureSkipVerify`, which is banned); `pin_sha256` is an additional leaf check.
  `wsconfig` must require `ca_file` (fix in wave B fix round). S15 uses `Event.SessionID()`.
- S16/S18 must call `api.ValidateFileMode` (≤ 0o777) on `write_file`; transport already refuses
  higher modes.
- `api.WorkspaceConfig` field names/units must equal `store.WorkspaceConfig`'s; the service maps
  one to the other field by field, tested.

Process (from the user's standing rules): agents run scoped checks while iterating and the full
gate once; one qa-reviewer per wave; only P0/P1 fixed before push; P2/P3 batched into a hardening
pass before M3 is done; push after each green wave.

### 0. OpenSandbox research (what it supports today, 13 Nov 2026)

- **Lifecycle server: no native TLS.** It is Python. `uvicorn.run(...)` is called with host, port, reload, log config, keep-alive, loop and http only. There is no `ssl_certfile` or `ssl_keyfile` and no CLI parser ([main.py](https://raw.githubusercontent.com/alibaba/OpenSandbox/main/server/opensandbox_server/main.py)).
  - The config reference has no TLS keys for the server, ingress or execd. Its only certificate keys are Kubernetes apiserver verification and egress MITM/upstream-proxy CAs ([server/configuration.md](https://raw.githubusercontent.com/alibaba/OpenSandbox/main/server/configuration.md)).
  - The spec's `servers` entry is `http://localhost:8080/v1` ([sandbox-lifecycle.yml](https://raw.githubusercontent.com/alibaba/OpenSandbox/main/specs/sandbox-lifecycle.yml)).
- **execd: no native TLS.** It calls `net.Listen("tcp4", ":"+port)` and then `http.Server{}.Serve(listener)`. It never calls `ServeTLS` ([execd/main.go](https://raw.githubusercontent.com/alibaba/OpenSandbox/main/components/execd/main.go)).
  - Default port is 44772. The auth header is `X-EXECD-ACCESS-TOKEN` ([execd.md](https://raw.githubusercontent.com/alibaba/OpenSandbox/main/docs/architecture/data-plane/execd.md), [execd-api.yaml](https://raw.githubusercontent.com/alibaba/OpenSandbox/main/specs/execd-api.yaml)).
- **No mTLS anywhere.**
- **Authentication:**
  - `[server].api_key`, sent as header `OPEN-SANDBOX-API-KEY`. The env var `OPENSANDBOX_SERVER_API_KEY` overrides it.
  - With no key set, the server only starts after a typed `YES` or `OPENSANDBOX_INSECURE_SERVER=YES` ([configuration.md](https://raw.githubusercontent.com/alibaba/OpenSandbox/main/server/configuration.md)).
- **Docker settings that matter to us:**
  - `[docker].network_mode` defaults to `host`. The egress sidecar and `networkPolicy` need `bridge`.
  - `[egress].mode` is `dns` (CIDR rules not enforced) or `dns+nft`.
  - `[secure_runtime].type` is `gvisor`, `kata` or `firecracker`, set with `docker_runtime` (e.g. `runsc`).
  - `no_new_privileges` (default true), `seccomp_profile`, `apparmor_profile`, `drop_capabilities` and `pids_limit` are all **server-wide**, not per request.
- **Bridge-mode networking:** one host port per sandbox maps to execd. The endpoint API can return a server-proxied URL `/sandboxes/{id}/proxy/{port}` (`use_server_proxy`, now marked deprecated) ([network architecture](https://mintlify.wiki/opensandbox-group/OpenSandbox/architecture/network), [lifecycle spec](https://raw.githubusercontent.com/alibaba/OpenSandbox/main/specs/sandbox-lifecycle.yml)).
- **Maturity:** server releases are still 0.1.x ([server v0.1.8 notes](https://newreleases.io/project/github/opensandbox-group/OpenSandbox/release/server%2Fv0.1.8)). Repo: [opensandbox-group/OpenSandbox](https://github.com/opensandbox-group/OpenSandbox).

These sources are the main branch today. S9 re-checks them against the release we pin.

### Node-local TLS front
- **The runner cannot be its own TLS front.** If the runner runs it in-process, the plaintext hop just moves to runner → OpenSandbox. Rejected.
- **The front must sit next to OpenSandbox**, ideally in the server's own network namespace (same pod, or compose `network_mode: service:opensandbox`):
  - The server binds `127.0.0.1:8080` inside that namespace, so plaintext never leaves it.
  - Only the TLS port is published, on the host's `127.0.0.1`.
  - execd traffic goes through the server proxy path, so the runner needs one front, one pin and one host. The server-to-execd hop stays inside OpenSandbox's own Docker bridge.
- **Front requirements:** TLS 1.3 only, and mTLS (it accepts only the runner's client certificate).
- **Who supplies the front is open question Q3.** I recommend a small stdlib subcommand `mirafleet runner tls-front`. It needs no dependency, and its routes are limited to `/v1/sandboxes*` and `/sandboxes/{id}/proxy/44772/*`. The alternative is a documented third-party proxy that the operator installs.
- **Certificates:** in both cases, `mirafleet runner tls-init` mints a per-node private CA, the front's server cert and the runner's client cert (ECDSA P-256, files 0600).

**Shipped (S19, decision 3): `mirafleet runner tls-init` and `mirafleet runner tls-front`.**
- `tls-init -dir DIR [-days N]` (DIR new or empty, created 0700) writes `ca.pem`, `front.pem`/`front-key.pem` (SAN `127.0.0.1`, `::1`, `localhost`) and `client.pem`/`client-key.pem`, all 0600, ECDSA P-256. The CA private key is discarded after signing. It prints the CA path and the front certificate's hex SPKI pin, ready to paste into `opensandbox:` in workspace.yaml (`ca_file`, `pin_sha256`, `client_cert`, `client_key`).
- `tls-front -dir DIR [-listen 127.0.0.1:8443] [-upstream 127.0.0.1:8080]` is a stdlib reverse proxy (`internal/workspace/osb/front.go`). TLS 1.3 only; a client certificate is required and verified against `ca.pem`; the listen address and the upstream must be loopback IPs and the upstream is plain `http`. Only `/v1/sandboxes` (and below) and `/sandboxes/{id}/(proxy|port)/44772/...` (optionally `/v1`-prefixed) are routed; everything else is 404 and never reaches OpenSandbox. Paths with dot segments, doubled slashes or backslashes are 404. The decoded path is re-encoded upstream, hop-by-hop and `Forwarded`/`X-Forwarded-*` headers are dropped, responses stream (SSE), and API keys and execd tokens are never logged (no headers, bodies or query strings are logged at all).
- Run it next to OpenSandbox, ideally in its network namespace, so that the plaintext hop never leaves it.

**Alternative: any existing TLS-terminating proxy** (nginx, Caddy, HAProxy, Envoy, a service mesh sidecar) in place of `tls-front`, with `opensandbox.front: external` in workspace.yaml. The runner enforces the same rules whichever front is used, so the proxy must provide:
- `https` only, TLS 1.3 only (`ssl_protocols TLSv1.3` or the equivalent), listening on a loopback address;
- a server certificate that chains to the `ca_file` configured on the runner (and, if `pin_sha256` is set, whose SPKI matches it);
- client certificate required and verified against a CA that signed only the runner's client certificate (mTLS);
- an upstream of `http://127.0.0.1:8080` (OpenSandbox's lifecycle server) and the same route allow-list as above, 404 for the rest; no redirects, no response caching, no buffering of `text/event-stream` responses;
- the `OPEN-SANDBOX-API-KEY` and `X-EXECD-ACCESS-TOKEN` headers passed through and kept out of access logs.
`tls-init` can still mint the CA and the runner's client certificate for such a proxy.

### Runner-side rules (checked when workspace.yaml loads; any failure stops the runner)
- The server URL must be `https://`. `http://` is refused.
- TLS: `MinVersion = MaxVersion = TLS1.3`. `RootCAs` comes only from the node CA, or `pin_sha256` is used (SPKI pin checked in `VerifyConnection`). The system pool is never used.
- The client certificate is required.
- No redirects are followed. Every URL is built from the configured base; endpoint hosts that OpenSandbox returns are ignored, and only their path is used after validation.
- `api_key_file` is required. It must be 0600 or 0400, owned by the runner's uid, and is never read from env or argv. The key and execd tokens are never logged or passed into a sandbox.
- `secure_runtime` must be declared for the runner to accept guarded fleets.
- Every create sends a deny-default `networkPolicy`. A server without bridge plus an egress sidecar therefore fails the create (fail closed). Docs require `egress.mode = dns+nft`.

### 1. Design decisions

### 1.1 Protocol: operator methods (api@ only)
- **New operator methods:** `workspace.open | exec | read_file | write_file | close | list`. They are added to `IsOperatorMethod` and the policy table, both on purpose.
- **New admin methods (admin socket only):** `fleet.workspace_set`, `workspace.admin_list`, `workspace.kill`. Lifecycle stays on central.
- **Method parameters and results:**

| Method | Params | Result |
|---|---|---|
| `workspace.open` | `{fleet, session, image?, labels?, confirm?}` | `{workspace:{id, fleet, runner, session, image, state, created, last_used, expires}, reused}` |
| `workspace.exec` | `{workspace, argv[], cwd?, env?, timeout_s?, stdin?:bool, confirm?}` | `{exit_code, stdout, stderr, truncated, timed_out, duration_ms, request_id}` |
| `workspace.read_file` | `{workspace, path, offset?, limit?}` | `{size, offset, length, mode, eof}` + body frame |
| `workspace.write_file` | `{workspace, path, offset?, truncate?, mode?, length, sha256, confirm?}` + body frame | `{size}` |
| `workspace.close` | `{workspace}` | `{}` |
| `workspace.list` | `{fleet?}` | the caller's own workspaces only |

- **`argv` only on the wire, no shell string.** M5's `exec` tool wraps a command string as `["/bin/sh","-c",cmd]`. A shell inside the container is fine, because the container is the boundary. The audit log then records exactly what ran.
- **Body frames (new):** the request frame stays ≤ 64 KiB. The file payload travels in one more length-prefixed frame of at most `api.MaxFileChunk = 1 MiB`.
  - For `write_file` and `exec{stdin:true}`, central reads that frame **only after** the policy, ownership and confirm checks pass, with a 30 s close-timer like `ReadRequestTimeout`. An unauthorised caller cannot make central buffer 1 MiB.
  - The client sends the body frame right after the request. SSH's 2 MiB channel window means that write never blocks.
  - For `read_file`, the JSON result is followed by one body frame.
  - Rejected: base64 inside JSON. It needs a larger request limit for every method, or tiny 48 KiB chunks.
- **Cancel and concurrency stay as in M2:** closing the channel cancels; more channels give concurrency; at most 8 channels per connection.
- **Additive result fields** (compatible under §7.12 versioning):
  - `runners.list`: `slots`, `free_slots`, `executor`.
  - `fleets.list`: `workspace {default_image, images, network}`.

### 1.2 Protocol: central → runner
- **One new channel type, `workspace@mirafleet`.** The op travels in the channel-open extra data as JSON `transport.WorkspaceRequest{op: create|exec|read|write|destroy|list, id, spec, argv, cwd, env, stdin_len, path, offset, limit, truncate, mode, length, timeout_ms}`, at most 64 KiB.
- **Bytes on the channel:**
  - For write and stdin, central streams exactly `length` raw bytes, then `CloseWrite`. A mismatch is an error.
  - The runner replies with one length-prefixed `transport.WorkspaceResult{code, message, exec?, file?, list?, duration_ms}`. For read, `length` raw bytes follow, then `CloseWrite`.
  - Central reads with hard limits: result ≤ `MaxResultBytes`, body ≤ the length it asked for.
- **Rejected alternatives:**
  - Reusing `exec@`: an exec@ request must only ever reach the actions guard, and mixing in workspace ops blurs that boundary.
  - A separate `file@mirafleet` channel: same runner handler and same trust, so it only doubles the plumbing. ARCHITECTURE.md should drop the `file@` name.
- **The runner refuses `workspace@` with `Prohibited` when no executor is configured,** and with `ResourceShortage` when it is busy.

### 1.3 Buffered output, no streaming
- **Exec results are buffered.** The runner captures a head and a tail of each stream and trims them so the **JSON-encoded** stdout+stderr fit `api.MaxResultBytes` (1 MiB). Binary or control-character output can therefore never turn into `too_large`. Output is sanitised to valid UTF-8.
- M5 applies its own 30 KB head+tail cap on top.
- **Rejected for M3:** streaming progress. api@ is one response per channel, and MCP tools return one result. M5 can add progress notifications later.

### 1.4 Scheduling and sticky sessions
- **The session is chosen by the client.** `session` matches `^[A-Za-z0-9._:-]{1,128}$`. M5 sets it to the harness session id (from the SessionStart hook) or a random id per MCP process.
- **Sticky:** there is at most one live workspace per (operator, fleet, session), enforced by a unique partial index.
  - `open` for a live session returns it with `reused:true`.
  - If that workspace's runner is offline, `open` returns `unavailable`. It never silently creates a fresh one, because the files are on that runner.
- **Placement:**
  1. Candidates: runners that are `active` and online, whose heartbeat `executor` matches the fleet's executor.
  2. Guarded fleets: the runner must advertise a `secure_runtime`.
  3. The requested `labels` must be a subset of the runner's **trusted token labels**.
  4. The image must match the runner's advertised image patterns. These are informational and used for placement only.
  5. `free = hb.slots − live rows in the store` (`opening`, `open`, `closing`).
  6. Pick the runner with the most free slots; random tie-break (crypto/rand).
  7. `Store.ReserveWorkspace` re-checks the count inside one transaction and inserts `opening`.
  8. On `ErrFull`, or when the runner answers `ResourceShortage`, try the next candidate (at most 3). Image or pull failures do not retry.
- **`concurrent: N` lives in the runner's workspace.yaml** and is reported as `slots` in the heartbeat. The store count is what central schedules from. The runner's own semaphore of N is a second gate. A runner that inflates N only overloads itself.
- **Per-operator cap:** `MaxWorkspacesPerOperator`, default 8, so one agent cannot take over a fleet.

### 1.5 Identity and ownership
- **Workspace id:** `ws_id` is 32 lowercase hex characters (128-bit `crypto/rand`), created by central.
  - The runner uses it as the container id `mf-<id>`, the directory `<root>/<id>` and the label `mirafleet.workspace`, and re-validates it with a regex.
  - Because central assigns the id, `Create` is idempotent and reconcile can map containers back to rows.
- **Ownership:** every call loads the row and requires `operator_id == principal.ID`. Anything else gets `not_found`, so existence does not leak.
  - Admins act through the admin methods only.
  - `workspace.list` returns only the caller's own workspaces.
- **Runner status:**
  - `disabled`: no new `open`, `exec` or `write`; `read`, `close`, `destroy` and the reaper still work. This matches M2's "new work refused".
  - `pending`: never gets workspaces.
  - The registry gains per-op gating: `destroy` and `list` are allowed on `active` and `disabled`; every other op needs `active`.

### 1.6 TTL reaper, revoke and reconcile
- **Reaper:** a central goroutine in the server wait group, stopped in `Close` before the store closes, using the injected clock, every 60 s. It moves these rows to `closing`, then calls destroy, then sets `closed`:
  - idle `open` rows (`last_used_at + idle_ttl < now`, default 24 h);
  - rows past their hard `expires_at` (fleet `max_ttl`, default 7 d);
  - rows whose operator or runner is revoked.
  A runner that is offline leaves the row in `closing` (it still holds its slot) until reconcile.
  Idle reaping counts from the later of `last_used_at` and central's start, so an outage longer than `idle_ttl` does not wipe every workspace on restart. Every op touches `last_used_at` at dispatch and again at completion, and a workspace with an op in flight is never idle-reaped. Reconcile destroys an `opening` row only when it is older than the open timeout plus 30 s, and moves an `open` row to `lost` when its container is listed as stopped, unknown or terminated. On runner restart the egress listener is re-attached only if `egress` is still allowed in the runner config.
- **Revoke:**
  - **Runner revoke:** after the M2 commit, `CloseWorkspacesOfRunner(reason "runner revoked")` runs in its own transaction with its own audit row. The reaper is the backstop if that write fails. The containers stay on that host, because it never reconnects. Docs point to `mirafleet runner workspace prune` (local).
  - **Operator revoke:** the M2 connection kick cancels in-flight execs. Their workspaces move to `closing` and the next reaper sweep destroys them.
- **Reconcile** runs when a runner first heartbeats (background goroutine, never under the registry lock). Central calls `list` and compares:

| Runner reports | Store row | Action |
|---|---|---|
| present | none, or closed/failed | destroy (orphan) |
| present | `closing` | destroy, then `closed` |
| present | `opening` older than the open timeout | destroy, then `failed` |
| missing | `open` | `lost` (slot freed, system audit) |

  Each runner restart also re-attaches the egress listeners.
- **Central restart:** at startup, `opening` rows become `failed` (we crashed mid-create). Reconcile cleans up when each runner returns.
- **Runner-local backstop:** a runner-local `max_age` destroys anything older, in case central is gone for good. The runner otherwise never deletes on its own.

### 1.7 Store (migration 0002)
```sql
CREATE TABLE fleet_workspace (
  fleet_id INTEGER PRIMARY KEY REFERENCES fleets(id) ON DELETE CASCADE,
  executor TEXT NOT NULL CHECK (executor IN ('containerd','opensandbox')),
  default_image TEXT NOT NULL,
  images TEXT NOT NULL CHECK (json_valid(images)),          -- allowlist: exact refs or repo@sha256:* / repo:* patterns
  pull TEXT NOT NULL CHECK (pull IN ('if-not-present','always','never')),
  network TEXT NOT NULL CHECK (network IN ('none','egress')),
  egress TEXT NOT NULL DEFAULT '[]' CHECK (json_valid(egress)), -- ["host[:port]", "*.domain:443", "cidr:port"]
  cpu_milli INTEGER NOT NULL CHECK (cpu_milli > 0), memory_mb INTEGER NOT NULL CHECK (memory_mb > 0),
  pids INTEGER NOT NULL CHECK (pids > 0), tmpfs_mb INTEGER NOT NULL, disk_mb INTEGER NOT NULL,
  idle_ttl_s INTEGER NOT NULL CHECK (idle_ttl_s > 0), max_ttl_s INTEGER NOT NULL CHECK (max_ttl_s >= idle_ttl_s),
  updated_at INTEGER NOT NULL);
CREATE TABLE workspaces (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  ws_id TEXT NOT NULL UNIQUE CHECK (length(ws_id) = 32),
  fleet_id INTEGER NOT NULL REFERENCES fleets(id) ON DELETE RESTRICT,
  runner_id INTEGER NOT NULL REFERENCES runners(id) ON DELETE RESTRICT,
  operator_id INTEGER NOT NULL REFERENCES operators(id) ON DELETE RESTRICT,
  session TEXT NOT NULL, image TEXT NOT NULL, spec TEXT NOT NULL CHECK (json_valid(spec)),
  state TEXT NOT NULL CHECK (state IN ('opening','open','closing','closed','failed','lost')),
  reason TEXT NOT NULL DEFAULT '',
  created_at INTEGER NOT NULL, last_used_at INTEGER NOT NULL, expires_at INTEGER NOT NULL, closed_at INTEGER);
CREATE UNIQUE INDEX workspaces_session_live ON workspaces(operator_id, fleet_id, session) WHERE state IN ('opening','open');
CREATE INDEX workspaces_runner_live ON workspaces(runner_id) WHERE state IN ('opening','open','closing');
CREATE INDEX workspaces_idle ON workspaces(last_used_at) WHERE state = 'open';
ALTER TABLE audit ADD COLUMN workspace TEXT NOT NULL DEFAULT '';
CREATE INDEX audit_workspace ON audit(workspace) WHERE workspace <> '';
```
- **State machine:** `opening → open | failed | closing`, `open → closing | lost`, `closing → closed | lost | failed`. `closed`, `failed` and `lost` are terminal. (`opening → closing` lets revoke destroy in-flight creates; `closing → lost` lets the reaper free rows on revoked or vanished runners.)
- **New Store methods** (every mutator takes `now`; state changes are atomic with their audit event):
  - `CreateFleet`: `Fleet.Workspace *WorkspaceConfig` is inserted in the same transaction (required when mode is workspace, forbidden otherwise).
  - `GetFleetWorkspace`, `PutFleetWorkspace`.
  - `ReserveWorkspace(ctx, w, slots, maxPerOp, now, ev) (Workspace, existing bool, error)`: on `existing`, nothing is written and the service audits the reuse. Returns `ErrFull`.
  - `SetWorkspaceState(ctx, wsID, from []State, to, reason, now, ev)`.
  - `TouchWorkspace` (not audited).
  - `GetWorkspace`, `ListWorkspaces(filter)`, `CountLiveWorkspaces(runnerIDs)`.
  - `CloseWorkspacesOf(runnerID|operatorID, reason, now, ev)`.
- `store.AuditEvent` gains `Workspace`.

### 1.8 Audit
- **Every workspace call writes rows,** `list` included (user requirement; an M2 list writes none).
  - `open`, `exec`, `write_file`, `read_file` and `close` write a `start` row **before** dispatch (fail closed: no row, no call) and an outcome row with the same `request_id`.
  - `list` and refusals write one row each.
- **What the rows contain:**
  - `exec`: argv JSON clipped to 4 KiB, `cwd`, and env **names only, never values**.
  - files: path, byte count and the SHA-256 of written data, **never content**.
  - outcomes: `ok`, `error`, `cancelled`, `timeout`, `denied`.
- The runner writes the same events to its local JSONL log.
- System actions use source `system`: reaper, reconcile, lost, revoke cascades.

### 1.9 Limits

| What | Limit |
|---|---|
| argv | ≤ 256 elements, ≤ 32 KiB total, no NUL |
| cwd, path | ≤ 4 KiB UTF-8, no NUL; relative to `/workspace` or absolute under it; cleaned; `..` escapes refused |
| env | ≤ 32 vars, names `^[A-Z_][A-Z0-9_]{0,63}$`, values ≤ 4 KiB |
| exec timeout | default 2 min, max 10 min (`api.ActionTimeout`; Q5) |
| open timeout | 5 min (image pull) |
| file op / close / list | 60 s / 60 s / 10 s |
| file chunk | 1 MiB per call; offset paging; file ≤ `max_file` (default 64 MiB) |
| exec output | JSON-encoded stdout+stderr ≤ 1 MiB, head+tail |
| concurrent execs | ≤ 4 per workspace (runner) |
| disk | soft quota (Q8): measured every 60 s and before writes; over quota refuses `write_file`; 2× over kills the workspace |

- Env has two filters: it must be in the runner's `env_allow`, **and** a hard denylist always applies (`*_API_KEY`, `*_TOKEN`, `*_SECRET*`, `ANTHROPIC_*`, `OPENAI_*`, `AWS_*`, `SSH_AUTH_SOCK`, `GIT_ASKPASS`, `*PROXY*`). The denylist is enforced on both central and runner.

### 1.10 Fleet config (central, admin only)
```
mirafleet central fleet create dev -mode workspace -executor containerd -image REF -images REF,REF@sha256:*,...
   -pull if-not-present|always|never -network none|egress -egress host:443,*.golang.org:443
   -cpus 2 -memory 4GiB -pids 1024 -tmpfs 512MiB -disk 10GiB -idle-ttl 24h -max-ttl 168h [-confirm]
mirafleet central fleet workspace set dev <same flags>
mirafleet central workspace list [-fleet F] [-json]
mirafleet central workspace kill ID
```
- **Images:**
  - The default image must be in the allowlist.
  - References are normalised with `github.com/distribution/reference`, which comes in with containerd already.
  - A tag-only pattern is allowed but warned about. Digests are recommended.
- **Guarded fleets** (`-confirm`):
  - `confirm == fleet name` on `open`, `exec` and `write_file`.
  - A secure runtime is required on both executors (Q4).

### 1.11 Runner config: `/etc/mirafleet/workspace.yaml` (the workspace-mode boundary, like actions.yaml)
```yaml
executor: containerd            # or opensandbox
concurrent: 4
max_age: 168h
images: ["docker.io/library/golang@sha256:*", "ghcr.io/acme/dev@sha256:*"]   # runner-side allowlist (boundary)
limits: {cpus: 4, memory: 8GiB, pids: 2048, tmpfs: 1GiB, disk: 20GiB, max_file: 64MiB}  # caps; above = refused
network: [none, egress]
env_allow: [LANG, LC_ALL, TERM, CI, GOFLAGS, NODE_ENV]
containerd: {address: /run/containerd/containerd.sock, namespace: mirafleet, snapshotter: overlayfs,
             runtime: io.containerd.runc.v2, secure_runtime: "", root: /var/lib/mirafleet/ws,
             userns: required, uid_base: 1000000, apparmor: auto}
opensandbox: {server: "https://127.0.0.1:8443", ca_file: ..., pin_sha256: ..., client_cert: ..., client_key: ...,
              api_key_file: /etc/mirafleet/opensandbox.key, secure_runtime: gvisor}
```
- **Strict parsing:** unknown fields are errors (`KnownFields`).
- **Fail-closed checks at load:**
  - namespace `k8s.io` or `moby` is refused;
  - `root` must be absolute, root-owned and 0700;
  - there is no "privileged" or "unconfined" option at all;
  - `images` must be non-empty;
  - the `userns: required` probe must pass;
  - the OpenSandbox rules in §0 apply.
- **Effective policy = fleet ∩ runner.** The runner builds the whole OCI spec itself from a fixed template. Central only supplies the image, limits within the runner's caps, the network mode and allowlisted env. A compromised central therefore cannot get a privileged container, a host network or a host mount.

### 1.12 Actions guard and workspace mode
- **`runner run` takes exactly one of `-actions FILE` or `-workspace FILE`.** Both together are refused.
  - One runner = one fleet = one mode.
  - The actions guard is never run as root just because containerd needs root.
  - The actions guard is unchanged. Workspace commands never run on the host.
- Central already refuses `action.run` on workspace fleets, and refuses `workspace.*` on actions fleets with `conflict`.
- Giving neither flag keeps the M2 behaviour (`-actions /etc/mirafleet/actions.yaml`). `-workspace` loads the file with `wsconfig.Load` (all file checks), builds the executor (`ctrd.New` or `osb.NewExecutor`) with the ownership name `<fleet>/<runner>` from runner.yaml (unique across fleets, C-16), and `runner.Config.Validate` runs before connecting. Workspace mode never falls back to actions.
- Local admin on the runner host: `runner workspace list` and `runner workspace prune [-all] -yes` talk to the executor directly (no central), so they work after a runner revoke. `prune` without `-all` removes workspaces older than `max_age`; nothing is destroyed without `-yes`. Until ctrd `List` filters on the runner label (C-16), give each runner on a host its own `containerd.namespace`: `list` and `prune` act on everything in that namespace.
- `mcp api METHOD [JSON] [-in FILE|-] [-out FILE]`: `-in` is the body of `workspace.write_file` (`length` and `sha256` are filled in when absent) or the stdin of `workspace.exec` (`stdin:true` is set); `-out` receives the `workspace.read_file` body (0600, atomic). Bodies are at most 1 MiB; larger files go in chunks with `offset`.
- A runner without actions refuses `exec@`; one without a workspace config refuses `workspace@`.
- **A workspace runner is root-equivalent:** access to the containerd socket amounts to host root. This goes in the docs and the security chapter.

### 1.13 containerd sandbox (default executor)
- **Namespace and connection:** containerd namespace `mirafleet`, default socket. Works on Docker Engine hosts, whose own containers live in namespace `moby`.
- **Process identity:**
  - Inside the container the user is uid/gid 1000:1000.
  - With `userns: required`, each slot gets its own host range: `uid_base + slot*65536`. The snapshot is idmapped (containerd 2 overlay idmap labels), so different workspaces are isolated from each other as well.
  - With `userns: off`, the host uid is `uid_base + slot`, never a real host user.
  - The workspace directory is chowned to the mapped uid, mode 0700.
- **Hardening:**
  - no new privileges; **all capabilities dropped**;
  - containerd's default seccomp profile (`contrib/seccomp`);
  - AppArmor default profile when enabled on the host (`auto`); `required` fails if it is unavailable;
  - default masked and readonly paths;
  - read-only rootfs;
  - mounts: `/workspace` (rw bind of the workspace directory, nosuid, nodev); `/tmp` (tmpfs, size limit, nosuid, nodev); generated read-only `/etc/hosts` and `/etc/resolv.conf`; `/.mirafleet/init` (read-only bind of the mirafleet binary, Q9).
  - **No other host mounts**, no devices beyond the defaults.
  - new namespaces for pid, ipc, uts, mount, cgroup and net (net is empty, loopback only), plus user.
  - cgroups: CPU quota, memory with swap equal to memory, pids limit; `nofile` rlimit.
- **PID 1:** `mirafleet workspace-init`, a stdlib zombie reaper that sleeps until SIGTERM. It works in any image, distroless included.
- **Network:**
  - `none`: no route out at all.
  - `egress`: the runner opens a listener on `127.0.0.1:3128` **inside the container's network namespace** (`LockOSThread` + `unix.Setns` + `Listen`, then setns back; the thread is never reused if setns back fails).
  - That listener feeds a stdlib HTTP/CONNECT proxy that enforces the host:port allowlist. The proxy does its own DNS and refuses loopback, link-local, metadata (169.254.169.254) and private ranges unless they are listed explicitly.
  - Execs get `HTTP(S)_PROXY`. Tools that ignore proxies fail closed.
  - No CNI, no iptables, no new dependency (Q2).
- **Exec:** `task.Exec` with an OCI `Process{Args, Cwd under /workspace, Env, User, NoNewPrivileges, no capabilities}`. stdio goes through containerd FIFOs into the capture buffers. A cancelled or expired context sends SIGKILL to the exec, then deletes it. Background children survive until close: daemonised or double-forked children also survive an exec timeout until the workspace is destroyed, bounded by the pids and memory limits.
- **Files:**
  - On the host, through `os.Root` (Go 1.24+ stdlib) opened on the workspace directory, so symlinks cannot escape.
  - Opened with `O_NOFOLLOW` where possible and `O_NONBLOCK`, then `fstat` must show a regular file, so FIFO or device tricks cannot hang the runner.
  - New files are `Fchown`ed to the workspace uid. Temp file plus rename on truncate-writes.
  - Only `/workspace` is reachable this way (documented).
- **Destroy:** kill the task (`KillAll`), wait, delete the task, delete the container with snapshot cleanup, close the egress listener, then `os.RemoveAll` the directory (it does not follow symlinks). Idempotent.
- **List:** label filter `labels."mirafleet.workspace"`.
- **Pull:** policy from the spec. No registry credentials in M3 (Q7). The image allowlist is re-checked on the resolved reference **before** pulling.

### 1.14 OpenSandbox mapping and gaps

| Executor op | OpenSandbox call |
|---|---|
| Create | `POST /v1/sandboxes {image.uri, entrypoint:["sleep","infinity"], env:{allowlisted only}, resourceLimits{cpu, memory}, timeout: max_ttl (≥60), metadata{mirafleet.workspace, mirafleet.runner}, networkPolicy{defaultAction:deny, egress:[allow …]}, volumes:[{name:"ws", pvc:{claimName:"mf-<id>", createIfNotExists:true, deleteOnSandboxTermination:true}, mountPath:"/workspace"}]}` (named volume, so no host path allowlist is needed) |
| Exec | `GET /v1/sandboxes/{id}/endpoints/44772?use_server_proxy=true` gives the path and headers (the execd token). Then `POST {base}{path}/command {argv, cwd, envs, timeout(ms), uid:1000, gid:1000}`, parsing SSE (`init` gives the id; `stdout`, `stderr`, `error.exit_code`, `execution_complete`). Cancel = `DELETE /command?id=` plus closing the stream. |
| ReadFile | `GET …/v1/filesystem/1000/1000/files/info?path=`, then `files/download?path=` with a `Range` header |
| WriteFile | `POST …/v1/filesystem/1000/1000/files/upload`, multipart (`metadata{path, owner, group, mode}`, then `file`) |
| Destroy | `DELETE /v1/sandboxes/{id}` (404 = done) |
| List | `GET /v1/sandboxes`, paged, filtered client-side on `metadata.mirafleet.runner` |

**Gaps:**
- No per-request read-only rootfs, seccomp, AppArmor or pids settings. They are server-wide, and the docs must require them.
- No stdin on `/command` (`exec{stdin}` returns `unsupported`).
- List metadata filtering is confirmed in the spec (S9, 13 Nov 2026): `GET /sandboxes?metadata=<urlencoded k=v&k2=v2>` (AND), plus `state` (repeatable, OR), `page` (from 1) and `pageSize`; the answer has `items` and `pagination{page,pageSize,totalItems,totalPages,hasNextPage}`. The `osb` client sends the filter and still re-filters client-side, so a server that ignores it cannot leak foreign sandboxes.
- `use_server_proxy` is confirmed deprecated: the spec says the server-proxied data path is in maintenance mode (security and bug fixes only) and that data-plane traffic should use the ingress gateway. It cannot be combined with `expires`. The spec's `Endpoint` schema also shows a `{host}/sandboxes/{id}/port/{port}` form, so the client accepts `/sandboxes/{id}/(proxy|port)/44772` (optionally `/v1`-prefixed), always rebuilt on the configured base. The front must route both; if the proxy path is ever removed, the front must forward `/port/{port}` and the runner needs the returned headers only.
- SSE through the server proxy is still unverified (the specs only say `POST /command` returns an event stream). Verify against a real server before M3 closes; the client sets `DisableCompression` and does not buffer.
- The `init` event shape is not defined in `execd-api.yaml`. The client reads the command id from `id`, falling back to `text`; `exit_code` appears on `error.error.exit_code` (non-zero or -1 for signals) and on `execution_complete` only for a successful foreground run (older servers omit it).
- execd exposes both unprefixed (`/files/...`) and identity-prefixed (`/v1/filesystem/{uid}/{gid}/files/...`) routes; the client uses only the identity-prefixed ones (501 on non-Linux, 503 if the identity cannot be set; no fallback). `/command` takes `argv` (or `command`), `timeout` in ms, `uid`/`gid` in the body.
- Pin-only trust is not supported: Go cannot verify a chain without a trust anchor except via `InsecureSkipVerify`, which is banned. `ca_file` is always required; `pin_sha256` is an extra check on the leaf (for a self-signed front, use the cert itself as `ca_file`).
- `timeout` must be ≥ 60 s.
- The egress `dns` mode does not enforce CIDRs.
- Policies carry no ports: an allowed host is open on every port inside the sandbox. The executor refuses rules for ports other than 443 and 80, so by this rule an allowed host is meant to be reachable on 80/443 only (not enforced by the server).
- The server is 0.1.x, so its API is not stable.
- Python runtime licences of what runs on the node are outside the linked-code scope, but list them in the docs.

### 2. Executor interface (final shape, `internal/workspace`, pure Go)

Docs name it "WorkspaceExecutor"; in Go it is `workspace.Executor`. Compared with docs/M3.md:
- `Create` takes a central-assigned ID instead of returning one.
- `Exec` takes a request struct with stdio; the timeout comes from the context.
- Files take offset and limit, and return their size and mode.
- `Name` and `Close` are added.

```go
type ID string // ^[0-9a-f]{32}$
type Spec struct {
    ID ID; Image string; Pull PullPolicy; Limits Limits /*CPUMilli, MemoryBytes, Pids, TmpfsBytes, DiskBytes*/
    Network Network /*Mode none|egress; Allow []EgressRule{Host string; Port int}*/
    RequireSecureRuntime bool; Labels map[string]string; MaxAge time.Duration
}
type ExecRequest struct { Argv []string; Cwd string; Env map[string]string; Stdin io.Reader; Stdout, Stderr io.Writer }
type ExecResult struct { ExitCode int; TimedOut bool; Duration time.Duration }
type FileInfo struct { Size int64; Mode fs.FileMode; ModTime time.Time }
type Info struct { ID ID; Image string; State State; Created time.Time; DiskBytes int64; Labels map[string]string }

type Executor interface {
    Name() string
    Create(ctx context.Context, s Spec) error                                   // idempotent on ID; ErrRefused, ErrUnavailable
    Exec(ctx context.Context, id ID, r ExecRequest) (ExecResult, error)          // ctx deadline = timeout; cancel kills
    ReadFile(ctx context.Context, id ID, path string, off, n int64) (io.ReadCloser, FileInfo, error)
    WriteFile(ctx context.Context, id ID, path string, r io.Reader, off int64, truncate bool, mode fs.FileMode) (FileInfo, error)
    Destroy(ctx context.Context, id ID) error                                    // idempotent; absent = nil
    List(ctx context.Context) ([]Info, error)
    Close() error
}
var ErrNotFound, ErrRefused, ErrBusy, ErrTooLarge, ErrQuota, ErrUnavailable, ErrUnsupported error
```
Helpers in the same package: `ValidID`, `CleanPath`, `ValidArgv`, `FilterEnv(allow)`, `MatchImage(patterns, ref)`, `Capture` (head+tail with a JSON budget), and `fake.Executor` for unit tests.

Metadata and private ranges are blocked. `setns` handling: thread locked, never unlocked on failure. Listeners are bound only inside the container's network namespace and closed on destroy.
- **S7:** every fail-closed rule is tested, with no silent defaults to insecure. Key file mode and owner are checked.
- **S9/S15:** no `InsecureSkipVerify`, no system roots, TLS 1.3 only. The pin is compared in constant time. Redirects are refused. Endpoint host rewriting stops SSRF and plain-http use.   - the spec has no capabilities, NNP, read-only rootfs, only the allowed mounts, and no host namespace;

- **S18/S19:** handlers map to DTOs only (store rows never on the wire). Bodies are read after gating. Timeouts. `-actions` xor `-workspace`. Secrets on stdin or in files only.
- **All steps:** no lifecycle or admin method is reachable on api@; agent API keys never enter a workspace (env denylist, MCP forwards nothing).
