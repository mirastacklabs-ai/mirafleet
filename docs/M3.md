# M3 — Workspaces: decisions

Parent: [PLAN.md](PLAN.md) M3. Design: [ARCHITECTURE.md](ARCHITECTURE.md). Detailed plan to follow.

## Carry-over from M2 (fix first in M3)
- Background runner `toucher` writes are not in central's wait group, so a queued
  `TouchRunner` can run after the store is closed at shutdown; drain or cancel touchers in
  `Server.Close` before the store closes.
- `mcp api` has a hard 2-minute call limit (`mcpCallTimeout`) while `action.run` allows
  `timeout_s` up to 600 s — align them (M5 replaces `mcp api`, but keep them consistent).

## Executor interface
Workspace mode runs behind one runner-side interface; scheduling, TTL reaper, `concurrent: N`
slots, audit and policy stay in mirafleet above it.

```go
type WorkspaceExecutor interface {
    Create(ctx, spec) (id, error)            // image, limits, labels
    Exec(ctx, id, argv, cwd, env, stdio) (exit, error)
    ReadFile(ctx, id, path) (io.ReadCloser, error)
    WriteFile(ctx, id, path, io.Reader, mode) error
    Destroy(ctx, id) error
    List(ctx) ([]Info, error)                // reaper and reconcile
}
```

- `containerd` executor (Go client): the default.
- `opensandbox` executor: opt-in per fleet (decision 13 Nov 2026).

## OpenSandbox executor (opt-in)
[OpenSandbox](https://github.com/opensandbox-group/OpenSandbox) (Apache-2.0, Linux Foundation /
AAIF) provides the sandbox; mirafleet keeps the agent and its API keys outside it and adds
identity, policy, central audit, instant revoke and outbound-only runners.

- **Transport: HTTPS only, never plain HTTP** — not even on loopback. TLS 1.3 via Go's
  `crypto/tls`; the runner pins the OpenSandbox server and execd certificates (fingerprint or a
  private CA configured per node), never the system CA pool; plain `http://` endpoints are
  refused at config load. If OpenSandbox can't serve TLS natively, M3 picks and documents a
  node-local TLS front (decided in the M3 plan, after verifying OpenSandbox's TLS support).
- **No SDK:** the runner speaks OpenSandbox's OpenAPI contracts with the Go standard library only
  — no new module dependency, nothing of theirs linked (their execd module pulls an MPL-2.0
  driver; irrelevant over the wire).
- **Hardened by default, enforced by the runner:** endpoints bound to the node only; refuse to
  start if OpenSandbox's API key is unset (the key lives on the runner host, never in a sandbox);
  bridge networking + egress policy; guarded fleets require a secure runtime (gVisor or Kata);
  no credentials passed into sandbox environments.
- **Verify before building:** OpenSandbox TLS support, transitive licences of what runs on the
  node, Podman/containerd compatibility, API stability (1.x is young).
- Not doing: mirafleet as an OpenSandbox provider, or central calling OpenSandbox directly
  (breaks the outbound-only model and splits the audit trail). Using `opensandbox-mcp` alongside
  `mirafleet mcp` needs no integration.
